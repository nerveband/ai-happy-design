Batch mode supports compact aliases for both command names and parameters. These reduce payload size and make batch JSON faster to write, especially for LLM agents generating operations.

## Command Aliases

Use these short names in the `command` field of batch operations:

### Creation Aliases

| Alias | Full Command | Domain |
|-------|-------------|--------|
| `frame` | `node.create_frame` | node |
| `rect` | `shape.create_rectangle` | shape |
| `ellipse` | `shape.create_ellipse` | shape |
| `polygon` | `shape.create_polygon` | shape |
| `star` | `shape.create_star` | shape |
| `line` | `shape.create_line` | shape |
| `svg` | `shape.create_from_svg` | shape |
| `image` | `shape.create_image` | shape |
| `text` | `text.create` | text |

### Styling Aliases

### Side-by-Side Example

Without aliases:
```json
{"command": "node.create_frame", "params": {"name": "Card", "width": 400, "height": 300}}
```

With alias:
```json
{"command": "frame", "params": {"name": "Card", "width": 400, "height": 300}}
```

## Parameter Shorthands

Use these short parameter names anywhere in batch `params`:

| Short | Full Parameter | Type | Example |
|-------|---------------|------|---------|
| `pid` | `parentId` | string | `"pid": "42:248"` |
| `w` | `width` | number | `"w": 400` |
| `h` | `height` | number | `"h": 300` |
| `sz` | `fontSize` | number | `"sz": 24` |
| `ff` | `fontFamily` | string | `"ff": "Inter"` |
| `lh` | `lineHeight` | number | `"lh": 140` |
| `bg` | `color` | string | `"bg": "#1a1a1a"` |
| `r` | `cornerRadius` | number | `"r": 16` |
| `fillColor` | `color` | string | `"fillColor": "#FF0000"` |

<Aside type="tip">
The `fillColor` to `color` alias is especially important. LLMs trained on other tools often emit `fillColor` instead of Figma's `color`. The system resolves this automatically. It is the number one silent failure from cross-tool training data.
</Aside>

### Side-by-Side Example

Without shorthands:
```json
{
  "command": "text.create",
  "params": {
    "parentId": "42:248",
    "text": "Hello World",
    "fontSize": 24,
    "fontFamily": "Inter",
    "width": 300,
    "cornerRadius": 8
  }
}
```

With shorthands:
```json
{
  "command": "text",
  "params": {
    "pid": "42:248",
    "text": "Hello World",
    "sz": 24,
    "ff": "Inter",
    "w": 300,
    "r": 8
  }
}
```

## Step Interpolation

Reference results from earlier steps using `${{steps.NAME.result.FIELD}}`:

| Reference | Meaning |
|-----------|---------|
| `${{steps.NAME.result.id}}` | Node ID from step NAME |
| `${{steps.NAME.result.width}}` | Width from step NAME |
| `${{steps.NAME.result.height}}` | Height from step NAME |
| `${{steps.NAME.result.x}}` | X position from step NAME |
| `${{steps.NAME.result.y}}` | Y position from step NAME |
| `${{steps.NAME.result.name}}` | Node name from step NAME |
| `${{steps.NAME.result.type}}` | Node type from step NAME |

The most common use is `${{steps.NAME.result.id}}` for `parentId`, wiring child elements to their parent frame.

```json
[
  {"name": "card", "command": "frame", "params": {"name": "Card", "w": 400, "h": 300}},
  {"name": "title", "command": "text", "params": {
    "pid": "${{steps.card.result.id}}",
    "text": "Card Title",
    "sz": 24
  }}
]
```

<Aside type="tip">
Step names should use `snake_case`. Names are auto-sanitized, but clean names prevent interpolation issues.
</Aside>

## Semantic Font Size Tokens

When `semanticTokens` is enabled on a parameter (like `fontSize`), you can use token names instead of pixel values:

| Token | Description | Value at 1080px | Value at 600px |
|-------|------------|----------------|----------------|
| `caption` | Smallest readable text | 36px | 20px |
| `body` | Base body text | 48px | 28px |
| `subheading` | Section subheadings | 64px | 36px |
| `heading` | Section headings | 84px | 48px |
| `title` | Page/card titles | 112px | 64px |
| `hero` | Hero display text | 152px | 88px |
| `display` | Largest display text | 200px | 116px |

These values are computed from canvas dimensions using the modular type scale (base = width * 0.044, ratio = 1.333).

```json
{"command": "text", "params": {"text": "Big Title", "sz": "hero"}}
```

<Aside type="note">
Semantic tokens require a canvas context. They work in batch mode (where canvas size is known) but may not resolve in standalone single-command mode.
</Aside>

## Alias Expansion Order

When a batch operation is processed:

1. **Command alias** expanded (`frame` becomes `node.create_frame`)
2. **Parameter shorthands** expanded (`pid` becomes `parentId`, `w` becomes `width`)
3. **fillColor alias** resolved to `color`
4. **Semantic tokens** resolved to pixel values (if canvas context available)
5. **Step interpolation** resolved (`${{steps.NAME.result.id}}` becomes actual node ID)
6. **Schema validation** runs on the fully expanded parameters

All expansion happens automatically. You never need to manually expand aliases.
